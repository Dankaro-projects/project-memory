# First-beta feedback and corrective release

The real-session feedback is justified. The memory preserved useful evidence, but the user still had to manage activation, capture completeness and HTML refresh. A working database and passing tests did not establish a dependable daily workflow. This review informed version 0.5.0b3; its recommendations were evaluated as evidence, not accepted automatically as product requirements.

The review covered the supplied session report and audit, the committed Claude integration at `e40c257`, existing code and documentation, and fresh execution in Codex, Claude Code and Chrome. The private report and project data remain local. The [aggregate evidence](verification-feedback-2026-09-14.json) and invented [reproduction case](../examples/feedback_case.py) are public.

## What failed and what changed

| Observed problem | Cause and correction | Remaining boundary |
|---|---|---|
| Configured hooks had no receipts. | Doctor now asks the actual Codex host about discovery and trust, separately from SQLite integrity and a subprocess MCP handshake. It reports missing, untrusted, duplicate and wrong-host hooks. | An already open task still needs its native tools checked. A subprocess handshake cannot establish that exposure. |
| Codex discovered the Claude plugin hooks. | The Claude hook file moved out of the conventional shared hook directory. The Codex manifest explicitly disables plugin hooks. Real discovery now finds only the nine project hooks. Claude plugin hooks skip capture when managed Claude hooks exist. | Keep one MCP connection enabled; this release does not silently reconfigure other installed connectors. |
| The user had to request the HTML and refresh it manually. | Setup opens the included local viewer. It reads SQLite through an authenticated, read-only loopback service, loads records in pages and source text on demand, and checks for changes while visible. | An explicit HTML export remains static. The local service stops after ten idle minutes and can be reopened with the same URL. |
| Changed Markdown required bespoke refresh scripts. | Session start and stop sync previously selected files. `check`, `sync` and their MCP equivalents expose changes and remaining pages. Identical text creates no new version. | New or moved files need explicit selection. PDF extraction and semantic approval remain separate. |
| A populated placeholder looked like a complete baseline. | Setup and health report `not_established`, recorded requirement count and unassessed coverage. Cost coverage distinguishes missing measurements from zero cost. | The system does not prove that the approved list covers every statement in every source. |
| A small context budget failed without a useful next step. | Errors expose the minimum size and a paged requirements route. Unchanged requirements can use a signature only while their complete text remains in current context. Omitted records expose bounded IDs and a search route. | Mandatory constraints remain mandatory. A signature cannot replace unread or lost context. |
| Review flags were difficult to act on. | A record explains which evidence changed, which explicit dependency was revised, or which requirement revision its decision used. | These are reasons to inspect evidence, not automatically accepted corrections or lessons. |
| A fresh Claude check rejected a document refresh. | The agent supplied a different subject. Refresh now retains the stored subject when omitted, and the tool describes that behaviour. Explicit attempts to change the subject still fail. | The assistant can still supply a wrong interpretation or ignore the schema. |
| A Codex continuity check created records for an acknowledgement. | Hook guidance now identifies a consequential approach choice as the reason to create a decision. The comparable rerun created no decision and preserved every checked fact. | One improved rerun does not establish that unnecessary administration is eliminated. |

SQLite history, source versions, evidence links, conditions and exceptions remain intact. Code reviews, writing corrections and research retain their subject boundaries. Capture remains mechanical; requirement approval, outcome assessment and lesson acceptance remain explicit. No runtime dependency or hosted service was added.

## Measurements

The [final public CI run](https://github.com/Dankaro-projects/project-memory/actions/runs/34828846714) passes all seven jobs: Python 3.11 and 3.14 on Windows, macOS and Linux, plus the browser check. The tested runtime commit is `c403e4027ab6dbe7a3763dddeb8dae989acbcf62`.

The baseline suite passed 112 tests before edits. The final local suite passed 130 tests, including separate HTTP processes, external SQLite writes, read-only enforcement, origin and capability checks, concurrent viewer launch, restart, timed evidence expiry, paging, subject retention and duplicate hook prevention. Tests complement the live checks below.

Public CI found an additional startup defect on hosted macOS. A captured stack showed Python’s HTTP server waiting in `socket.getfqdn` during listener setup. This service uses a fixed loopback address, so it now binds directly without hostname resolution. Failed startup also terminates and reaps its child process. A regression case rejects any hostname lookup; the actual hosted runners rerun the HTTP cases.

Windows CI also exposed two incorrect test assumptions. The source assertion now compares preserved bytes, including CRLF, and the expiry test establishes a current response before crossing its deadline. The runtime continues to preserve original text. On Python 3.11 the failed multiline assertion spent enough time generating a diff to exhaust the job limit; correcting the byte comparison also removes that artificial delay.

The same invented workflow uses 24 requirements, 31 sources and 20 selected Markdown files. Timed operations use five warm samples on one macOS machine. These numbers measure local functions and serialized MCP responses, not human productivity.

| Scripted measurement | 0.5.0b2 | 0.5.0b3 |
|---|---:|---:|
| First complete context, characters including MCP envelope | 11,166 | 11,479 |
| Repeated context after its full requirements were read | 7,050 | 650 |
| Context retrieval, median milliseconds | 2.05 | 2.21 |
| Explicit document refresh commands needed after a hook | 1 | 0 |
| Offline export, median milliseconds | 1.47 | 1.43 |
| Live source page, median milliseconds | Unavailable | 0.69 |

The first context grows slightly because it now states scope and recovery information. The repeated reply becomes smaller because already-read requirements are referenced precisely. This is not a promise of a similar saving across a session. The original feedback also recorded fast warm retrieval and export; orchestration, missing setup steps and repeated administration explain more of the reported friction than demonstrated slow SQLite queries. No browser paint-time baseline was recorded.

In actual Codex execution:

- Host discovery reports nine trusted project hooks, zero duplicate hooks and zero Claude hooks. The combined CLI and app-server runs observe all nine lifecycle event types.
- A command writes one marker, is interrupted, and resumes through a new host process. The marker remains exactly once. Seven recovery MCP calls succeed without an adapter error. One execution receipt remains unconfirmed because the sleeping process completion cannot be established.
- The first continuity run preserves all four facts but makes six MCP calls and creates an unnecessary episode, source and decision. After the guidance change, the comparable run preserves the same four facts with one MCP call and no writes. Both retain strict UTF-8, rejection of invalid bytes, the tagged Latin-1 exception and an unmeasured production outcome.
- The largest reported complete model inputs are 17,091 tokens before interruption and 22,804 during recovery. Continuity maxima are 17,027 before the guidance change and 16,112 after it. The below-10K target remains unmet. No feature or condition was removed to force a pass.

In two actual Claude Code 2.1.270 CLI sessions, the same prompt uses native health, context and document tools, reads the selected file and preserves four checked facts. Reported turns fall from nine to six and duration from 35,263 to 20,185 milliseconds. The first final account reports one subject correction; the second reports none. These correction counts are agent reports, not a complete tool-error trace. The sessions share a project but differ in cache and receipt state, so this is an illustrative rerun, not a controlled speed comparison. Both outputs add prose around the requested JSON and therefore fail strict output-format compliance. Live Claude interruption and compaction are not established by this trial.

Chrome verification observes an external write without reloading the page, an open decision switching to Needs review after a file change, and a concrete source reason. Stopping the service shows a disconnect message and last successful check; restarting reconnects at the same URL while retaining the selected view. Search pagination shows 25 and then six of 31 matching sources. HTTP tests independently reconstruct complete source slices and check WAL commits and expiry. The fresh installed wheel also serves the live viewer outside the checkout; offline export, backup and removal continue to work.

## Reproduce

Run the regression suite and packaging checks from the checkout:

```sh
python -m unittest discover -s tests -q
python -m examples.feedback_case
python -m examples.document_case --output results/documents
python -m examples.host_example --output results/host-example
node tests/viewer_logic.cjs
python scripts/build_bundle.py
uv build --out-dir dist/feedback
python scripts/check_artifacts.py dist/feedback
python scripts/installed_smoke.py dist/feedback
```

For the exact baseline, extract `git archive e40c257` into an empty directory and run the current `examples/feedback_case.py` with `PYTHONPATH` pointing at that directory. The script prints the imported version; verify that it says `0.5.0b2`. Use a fresh output directory for each live harness:

```sh
project-memory setup --project /absolute/path/to/test-project --client codex --trust --no-view
python -m examples.codex_interrupt --project /absolute/path/to/test-project --output results/interrupt
python -m examples.codex_lifecycle --project /absolute/path/to/test-project --output results/continuity
python -m examples.context_audit results/interrupt
```

These harnesses require a signed-in local Codex, execute invented work and retain private logs under the selected output directory. The input audit correctly exits unsuccessfully when any measured full input reaches 10K. For a browser check, open `project-memory view`, change a selected Markdown file or commit a record from another process, then inspect the same page and open record without exporting again. [Setup instructions](setup.md) describe sync, recovery and offline export.

For the Claude case, create a fresh project containing `SCOPE.md` with these two sentences: "Read all evidence before approving a requirement. Keep UTF-8 strict, except on the tagged legacy endpoint which uses Latin-1. Production effect is unmeasured." Run setup with `--client claude --trust --document SCOPE.md --no-view`, then execute from that project:

```sh
claude -p --output-format json --no-session-persistence --setting-sources project,local \
  --strict-mcp-config --mcp-config .mcp.json --permission-mode dontAsk \
  --allowedTools 'mcp__project_memory__*' 'Bash(cat *)' -- \
  'This is a bounded local Project Memory beta verification. Do not delegate, browse the web or inspect other projects. Use the native memory_get health and memory_context research tools. Read SCOPE.md using cat. Capture SCOPE.md through memory_write document with its absolute path. Return JSON with baseline_status, strict_encoding, legacy_exception, production_status and whether a duplicate source version was created. Use only these local facts. Do not approve requirements or create lessons.' > claude-result.json
```

Keep the raw result private. Inspect the actual hook receipts and source versions separately; a successful CLI exit does not establish correct tool use or output formatting.

## Unresolved limitations

This is a more usable beta, not demonstrated autonomous project governance. Semantic coverage across vision, ideas and capabilities still needs an explicit source-to-requirement review. Hashes detect textual change; they cannot judge whether a product direction remains appropriate. The assistant can still overlook evidence, omit a dependency, misclassify a statement or fail output-format instructions.

Daily completion, human reminders, repeated research, net maintenance time, long-term drift and competing tools have not been measured in a representative user trial. The small cases above must not stand in for those measurements. Real failures and difficult work remain in the evidence; no improvement claim uses a denominator reduced by avoiding them.

The native host controls the complete model input. Requirements signature reuse helps only while the original constraints remain available; it is not durable semantic compression. Large derived-status and drift views can still scan matching records. The loopback service is local and read-only, not an operating-system daemon or a multi-user web application.
